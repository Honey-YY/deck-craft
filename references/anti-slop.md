# 反 AI 味规则

「一眼看出是 AI 做的」不是因为难看，是因为**可预测**。同几个套路在无关的题材里反复出现，读的人就认出机器了。

规则来自 [alchaincyf/huashu-design](https://github.com/alchaincyf/huashu-design) 的设计评审标准与默认审美禁区，按 deck-craft 的轻量定位裁剪。

---

## 一、八条禁令

写之前先扫一眼这张表。踩任何一条，稿子立刻降一档。

| # | 禁 | 为什么 |
|---|---|---|
| 1 | **每页同一套装饰**（顶条 + 编号 + 全大写英文小标） | 这是 AI 最明显的指纹。真设计师不会让 14 页长同一个额头 |
| 2 | **单页自带页码** | 页码归外壳管。页面里写页码，和放映器的进度会打架 |
| 3 | **激进紫/蓝渐变当万能公式** | `linear-gradient(135deg,#3b2af9,#b547e4,#f335ec)` 这类，见过太多次 |
| 4 | **均匀深底 + 通用霓虹 glow** | 深色不是问题，「没有理由的深色 + 发光」才是 |
| 5 | **圆角卡片 + 左/上彩色边条** | 卡片方阵 + accent 边，是仪表盘套路的搬运 |
| 6 | **封面加个人署名 / 水印** | 作品集需要，演示稿不需要 |
| 7 | **emoji 当图标** | 换几何符号或纯文字，或干脆不要图标 |
| 8 | **数据页默认「三个大数字 + 条形图」** | 换什么配色都长一样，因为形态没跟着数据的关系走 |

**注意**：禁的是"没有意图"，不是"暗色"或"渐变"。用了可以，但你得写得出为什么。

## 二、色彩：采样 → 收敛 → 论证

不要从预设主题里挑。三步走：

### 1. 采样

主色从三个来源取，不凭空发明：

- **品牌资产** —— 用户给了 logo / VI，直接吸色
- **内容真图** —— 产品截图、摄影素材里的主导色
- **文化语境** —— 主题自带的色彩记忆（金融=墨绿/藏蓝/金；医疗=青灰/雾白；教育=靛蓝/米黄）

实在都没有，才用下面四套现成的，且**必须能说出它和题材的关系**。

### 2. 收敛

压到 **2–3 个有彩色 + 1 组中性色**。

用 oklch 判断：有彩色之间色相角差 ≥60°，或明度差 ≥0.3。中性色写成明度序列（L 0.15 / 0.35 / 0.65 / 0.92 / 0.98）。

**压 chroma**（这是让颜色显高级的关键）：

| 用途 | chroma | 说明 |
|---|---|---|
| 大面积底色 | 0.01–0.04 | 接近纸，不刺眼 |
| 主色 / 强调 | 0.08–0.15 | 油墨感，够醒目但不塑料 |
| 小面积点睛 | 0.15–0.22 | 保留活力，仅限按钮、关键词 |
| > 0.25 满版 | 避免 | 屏幕荧光感 |

原因：油墨印在纸上达不到屏幕的最大饱和度，人眼几十年被印刷品训练出的"高级感"就是那层物理灰度。刻意压 chroma 是在借用这个记忆。

### 3. 论证

**一句话写出「为什么是这个色」。写不出来，说明你在抄配方。**

写进交付说明，例如：

> 主色取自用户 logo 的赭石，chroma 压到 0.09 模拟油墨。

这条是防 slop 的自检门，不是仪式。

## 三、量化标准

数字比形容词可靠。交付前逐条对。

| 项 | 标准 |
|---|---|
| 标题字号 | 正文的 **2.5–3 倍**（1920 画布：正文 ≥24px，标题 60–120px） |
| 标签 / 注释 | ≥ 16px |
| 有彩色数量 | ≤ 3（含强调色） |
| 字体家族 | ≤ 2 |
| 间距 | 8pt 网格：8 / 16 / 24 / 32 / 48 / 64 / 96 |
| 留白占比 | ≥ 40%（极简 ≥60%） |
| 对齐 | 全局一种，不混用居中与左对齐 |
| 视觉层级 | 3–4 个清晰层级，不靠颜色区分，靠大小与粗细 |

**眯眼测试**：眯起眼看页面，层级还在吗？糊成一片就是层级不够。

---

## 四、数据页：先问关系，再选形态

「三个大数字 + 条形图」之所以是模板答案，是因为它不关心数据说了什么。

先问这组数字要表达哪种关系：

| 关系 | 形态 |
|---|---|
| **比例** | 按比例缩放的实物、面积图、堆叠条 |
| **变化** | 一条叙事曲线，标注拐点，而不是均匀的柱 |
| **构成** | 拆开的整体——爆炸图、分层、切片 |
| **对比** | 左右对照、上下叠放、并置 |
| **规模** | 一个超大对象占满版面，数字压在上面 |

数据本身可以是这一页的主角素材，不必让位给图表框。

---

## 五、删一遍

交付前对每个元素问：**删掉它，设计会变差吗？**

不会，就删。

最常被删掉的三类：

- 装饰性分隔线（换成留白）
- 装饰性图标（标题已经说清了）
- 为了填充而存在的第二行说明

---

## 六、评审的先后顺序

先看概念，再看执行。执行是放大器——放大一个空洞的概念只会更空洞。

**一票否决**：盖住所有文字和 logo，还认得出题材吗？换个客户名还成立吗？成立就是模板，概念分 ≤5，整体封顶。

对 deck-craft 落地的检查：

- [ ] 这份稿子的视觉母题是什么？一句话说得出来吗
- [ ] 把标题换成另一个行业的话，版式还成立吗（成立=要改）
- [ ] 删掉顶部装饰条，稿子变差了吗（没变差=删掉）
- [ ] 色彩能论证吗
- [ ] 眯眼测试过吗
- [ ] 有没有连续三页长得一样

## 出处与范围

本文件的禁令、量化标准、色彩推导协议、数据页形态表，提炼自 [huashu-design](https://github.com/alchaincyf/huashu-design)（花叔，MIT）的 `references/critique-guide.md`、`references/design-styles.md`、`references/modules/deck.md`。

原 skill 是 226 MB、带 84 种风格样张、playwright 视觉体检、Python 脚本链的完整工程。deck-craft 只取其中**能用一条规则表达、能被 `check.mjs` 拦住**的部分——重工程那套不搬，搬了就不叫零依赖了。
