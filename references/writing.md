# 写作规范

页面上的字，决定了稿子好不好。版式只负责让它看起来是对的位置。

---

## 标题：必须是一个判断

标题是整页最重要的 10 个字。它应该让听众在读到它的三秒内，知道你要说什么。

### 三个可套用的公式

**判断句** —— `X 是 Y`／`X 应该 Y`
> 中端价格带是未来两年的主战场
> 这个功能不该做

**因果句** —— `因为 X，所以 Y`／`X 导致 Y`
> 渠道成本上涨倒逼我们改直营
> 三个对手都在补同一块短板，窗口只剩两个季度

**量化句** —— 数字 + 结论
> 六成用户在第三步流失
> 单价降 15% 换来两倍复购

### 反面清单

| 坏标题 | 为什么 | 改成 |
|---|---|---|
| 市场分析 | 分类名 | 市场正在向中端集中 |
| 产品规划 | 分类名 | 下季度只做三件事 |
| 竞争格局 | 分类名 | 三个对手都在补同一块短板 |
| 用户调研结果 | 分类名 | 六成用户卡在第三步 |
| 关于 XX 的思考 | 等于没说 | 直接写那个思考 |
| 工作总结 | 分类名 | 这个季度我们验证了一件事 |

### 长度

- `h1`（封面/章节）：8–16 字，超过 16 字手动 `<br>` 断行
- `h2`（内页）：8–22 字
- `h3`（卡片/要点）：4–14 字，名词短语即可

一行放不下的标题，说明你要拆成两页。

## 支撑点：一句话说完

### 结构

```
[标题] 结论
   [支撑 1] 事实 / 数据 / 机制
   [支撑 2] 事实 / 数据 / 机制
   [支撑 3] 事实 / 数据 / 机制
```

支撑点回答的是「凭什么」。不是「还有哪些相关信息」。

### 三种有效支撑

| 类型 | 写法 | 例 |
|---|---|---|
| 事实 | 发生了什么 | 上季度三家同行同时降价 |
| 数据 | 量化的证据 | 我们的客单价是他们的 1.4 倍 |
| 机制 | 为什么会这样 | 因为渠道分成结构不同，我们让不出这个价 |

### 无效支撑（删掉）

- 「非常重要」「意义重大」——形容词不是支撑
- 「众所周知」「业内普遍认为」——没有主体的引用
- 「我们要重视 XX」——行动口号，不是论据
- 「进一步优化」「持续提升」——什么都没说

## 数字

### 三条硬规则

1. **有锚点** —— 相比什么、什么范围、什么时间
   - ✗ 提升了 300%
   - ✓ 相比上季度提升 300%（样本：全部 42 家门店）

2. **有出处或标注** —— 来源、口径，或明确写「示意」
   - ✗ 市场规模 8000 亿
   - ✓ 市场规模约 8000 亿（第三方口径，2025）

3. **能取整就取整** —— 「约 8000 亿」比「8237 亿」好读，除非精确值是重点

### `stat` 页的数字

- 主数字控制在 1–4 位有效数字（`74%` / `1.4×` / `8000`）
- 单位放 `<em>` 里，别混进主数字
- 三个数字必须是**同一量纲**的对照（都是增速、都是占比），不要混着放

### `chart` 页

- 条形高度按最大值算百分比，手写 `style="height:72%"`
- 不要让最小条低于 8%，否则看不出高度，改成 `bullets`
- 图例最多三条。第四条说明你该拆页

## 语气

默认：**克制、具体、不用形容词堆砌**。

### 按受众调

| 受众 | 特征 |
|---|---|
| 投资人 | 结论前置，数字密集，少修饰。第一页就要说清「为什么值得投」 |
| 内部平级 | 可以直接、可以有情绪，可以有「我们搞砸了一件事」 |
| 上级/管理层 | 结论 + 决策点 + 风险。他们要的是「要我拍什么板」 |
| 客户 | 少讲自己，多讲对方的问题。第一页不要放公司介绍 |
| 学生/培训 | 可以慢一点，多用例子和类比，可以重复核心结论 |

### 禁用词

```
赋能 · 抓手 · 闭环 · 打通 · 深度融合 · 全面提升
全方位 · 一站式 · 生态化 · 攻坚 · 发力 · 提质增效
```

除非是产品正式名称，否则一律换成具体说法：
- 「赋能团队」→「让团队自己就能做」
- 「闭环」→「从下单到复购都在一个系统里」
- 「打通数据」→「三个系统用同一套用户 ID」

### 可以用

- 短句。一个句子一个意思。
- 具体的名词和动词。「砍掉两个渠道」优于「优化渠道结构」。
- 自嘲和诚实的判断。「这块我们还没想清楚」比硬编一个方案可信。

## 页面文字的密度

一页 720px 高，正文安全区约 480px。

| 元素 | 上限 |
|---|---|
| 标题 | 1 行（h1 最长 2 行） |
| 正文段落 | 每段 ≤ 45 字 |
| 一页总字数 | ≤ 120 字（不含页脚） |

超了就是该拆页。**演示稿不是文档**——详细内容放讲稿里，页面只放路标。

判断法：把页面截图缩小到手机大小，还能读出标题和主要结构吗？读不出就是太密。

---

## 讲稿与页面分离

页面写**结论**，讲稿写**过程**。

如果某个信息必须口头补充才能理解，那它就不该占页面空间。反过来，如果一页的文字你需要逐字念，那这份稿子就变成了 Word 文档。

自检问题：**观众拍下这一页，回去能复述出你要说的那句话吗？**

## 常见坏稿的改法

### 症状：每页标题都是名词

> 市场分析 / 用户画像 / 竞争格局 / 产品规划

**改法**：每页先写一句「所以呢？」，那句话就是标题。

### 症状：一页三块内容

**改法**：找出最强的一块留在这页，另外两块各开一页。页数不够就砍——15 页讲三件事，好过 10 页讲十件事。

### 症状：全是形容词，没有事实

> 我们取得了显著的成果，团队能力得到全面提升

**改法**：换成具体事件或数字。「从 3 人扩到 11 人」「交付周期从两周压到三天」。

### 症状：数据堆砌，没有结论

> 一张表里 20 个指标

**改法**：只留三个能支撑你判断的指标，其余删。表格只留 3–6 行。

### 症状：讲完了但不知道要对方干什么

**改法**：`end` 页明确写出：要谁、在什么时候、做什么决定。
